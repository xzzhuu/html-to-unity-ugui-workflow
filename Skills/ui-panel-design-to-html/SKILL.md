# Unity UI 面板与可复用元素工作流

先确认面板预览，再确认当前项目所需的元素组图；之后按用户意图选择 HTML 转换或 Unity MCP 直接替换。交付到项目的内容包括元素素材、面板预制体，以及用户确认后的元素组图和完整面板预览参考图，不为视觉效果创建或修改 C#、主题 ScriptableObject、Shader 或临时 Editor 脚本。复用现有业务逻辑与原生组件。

## 选择入口与分支

- 只要求“新文件目录”或 HTML 工作区：运行初始化与结构校验，交付未审核草稿后停止，不设计业务控件或制造审批。
- **分支 A：完整流程**。未明确限定仅视觉优化的面板设计请求，默认走面板确认 → 元素组图确认 → HTML 实现与验收 → 用户要求时转换到 Unity。
- **分支 B：仅视觉优化**。用户明确只优化原有面板视觉时，面板确认 → 元素组图确认 → Unity MCP 直接导入并替换原内容。不生成 HTML/CSS/JS，不执行浏览器验收、转换器或其安装步骤。
- 已有面板预览或工作区：核对其确认记录与文件版本，从适用阶段继续，不重复已完成步骤，不擅自清理已有实现。更改组图只重新确认受影响组；布局或整体视觉变化才重新确认面板。

## 共用设计规则

- 仅制作当前需求实际涉及的组件和状态。Button、Toggle、InputField、Dropdown、Slider、Scrollbar、Scroll View 是参考类型，不是制作清单。先核对已有 Prefab、绑定与 Sprite；不因列举了类型而新增控件或改变业务职责。
- **默认设计布局为 1920×1080**。新建适用的屏幕 Canvas 时使用相应 Canvas Scaler 参考分辨率；已有明确配置优先沿用并记录差异。World Space Canvas 保持项目的世界尺寸和 XR 配置，以参考布局组织 RectTransform，不擅自切换 Canvas 模式。
- 尽量保持原始素材尺寸与像素细节，不按 RectTransform 显示尺寸缩小源图。检查 Max Size、压缩和平台覆盖，避免意外降质；VR 清晰度结合观看距离与世界尺寸验证，不能仅凭 1920×1080 宣称达标。低分辨率源图需要重制时报告；直接放大不视为恢复细节。
- **所有新制或本次正式导出的元素素材贴图**（包括底板、按钮、边框、图标、进度图形等）的宽和高均采用 **2 的幂次方**（可为长方形，例如 1024×128）；优先向上选择尺寸，不降低原始细节。优先从矢量源按目标尺寸重制，位图保持原像素，不强拉伸。0.3.0 HTML 转换不支持非整图 contentRect 的透明补边：优先重制为无需补边的 POT 素材；需要补边时先转人工适配，不登记为可直接转换。记录有效区域和九宫格。纹理尺寸与 RectTransform 显示尺寸独立。元素组图和面板预览属于参考图，保持原布局分辨率（默认 1920×1080），不强制变为 POT 或裁切。
- **每张面板预览使用纯色画布背景，画布颜色必须与面板主体/元素图片的主色明显区分**，以清楚显示边界、圆角和透明效果。例如深色面板使用中性灰色画布；不把面板主色直接作为画布色。各面板可复用同一合适的对比底色，不必各用不同颜色。不叠加庭院场景、照片、纹理、棋盘格或其他环境装饰。每个面板单独输出，清楚标注画布宽×高和面板主体宽×高，标注放在主体外，不遮挡界面。透明度在纯色底上检查；额外明暗背景验证若实际需要，另存验收证据，不混入供确认的正式面板预览。
- **VR 项目的所有元素组件素材不设计边缘描线、轮廓线或细描边框**，包括按钮、底板、内衬和进度图形；不额外导出 Outline/Border 轮廓素材。使用实色/半透明填充、明暗、间距与留白区分层级和状态，保留平滑 Alpha 圆角。装饰性细分隔线优先改为留白。九宫格 border 是切片边距元数据，可正常使用；审核图的尺寸标注线不属于运行时素材。实际 VR 锯齿仍须设备验证，不因去掉描边宣称已解决。
- **多面板总览必须清楚显示每张完整画布的独立区域**：保留整个 1920×1080 范围，以一致比例展示，用与画布不同色的间隔区或审核边界框分开。不得把同色画布无缝拼接，也不得把每个面板分别裁切放大到看似一样大。标明主体宽高，以及占画布宽、高的百分比；必要时补充面积占比。画布边界框和尺寸标注仅用于审核，不属于 VR 运行时组件的描边。
- 相同形状仅颜色不同，只输出一份白色或统一中性色素材，保留透明度，用各物体的 `Image.color` 改色；按钮颜色状态使用原生 Selectable Color Tint。形状、纹理或透明度结构不同才增加素材；真实多色图案不强行合并为单色遮罩。
- **素材、元素组图使用组件缩写前缀**，例如 `Btn_Primary_Background.png`、`Tgl_Option_Checkmark.png`。跨组件共用素材用 `Img`。完整映射与命名规则见 [组件与素材命名](references/component-naming.md#素材与元素组图命名)。不为了素材命名批量改动现有物体名、绑定或 GUID。
- 文字保留为 TMP，普通界面沿用项目 UIKit/UIRoot 管理和正式 Prefab 路径。保护 GUID、组件引用、UnityEvent 和序列化字段；不绕开项目流程创建独立普通 Canvas。

## 共用步骤与确认节点

| 步骤 | 动作与产出 | 确认节点 |
| --- | --- | --- |
| 1. 需求核对 | 核对原有面板与素材，记录实际需要的类型、元素、用途、状态和引用位置 | 仅把实际需求写入清单 |
| 2. 整体预览 | 制作完整面板预览，使用纯色画布，标注画布及面板主体宽×高；检查布局、半透明效果、文字及按钮对比度 | **面板预览图确认** |
| 3. 独立元素组图 | 每个可复用结构单独成图，展示尺寸、必要状态、图层、九宫格与在面板中的拼接效果；配色演示共用中性素材 | **元素组图确认**，逐组记录真实确认和版本 |
| 4. 素材导出 | 导出拆分 PNG，记录组件前缀、原始/导出像素尺寸、边距、用途、tint 与面板使用位置 | 与已确认组图对应，不用整图裁片代替可编辑控件 |

面板未确认前不制作正式元素组图；元素组图未确认前不进行最终素材导出、HTML 制作或 Unity 替换。组图审核可以包含中间素材候选，最终交付必须来自已确认版本。两次确认均须来自用户真实意见；使用已有批准图时记录适用版本与限定条件。

两个分支共用 `design/element-groups.json` 与审核记录，格式见 [清单与确认契约](references/manifests.md)。初始化不生成批准记录；结构校验不能替代视觉判断。

## 分支 A：HTML→Unity

元素组图确认后，读取 [HTML 契约](references/html-contract.md)，确定语义化物体名、原生类型、绑定、动态 Item 和辅助节点，生成 HTML/CSS/预览 JS 及清单。按确认尺寸对照面板和组图验收布局、外观及实际需要的状态；用现有比较脚本辅助判断。只有两次审批与 HTML 验收证据有效时标记 `ready`。

用户要求转换时，使用项目已有 `com.nexvr.html-to-ugui`，按其 README 操作；不擅自安装依赖。需要编辑器操作时使用可用的 Unity MCP 工作流。HTML/CSS/JS、清单和确认记录保留在工程外；已确认的元素组图和完整面板预览另导入 Unity 作为参考图。先查看只读导入计划，默认 stagingRoot=Assets/HtmlToUGUIStage/{PanelName}，将 Sprite、Item、主 Prefab 与报告整批生成到暂存目录。Skill 包开启 requireSkillApproval，字体复用项目 TMP 默认字体及现有材质。导入窗口更新 Assets/HtmlToUGUIStage/StageScene.unity，原场景保持不变。通过 Tools → HTML to UGUI → Stage Panels 窗口逐个预览面板，勾选需要的面板并查看复制计划后，才复制到正式目录；复制会重定向 Item 和图片引用，保留暂存内容。正式目录仅包含运行资源，复制记录保留于暂存目录。已有业务面板仍需项目适配以保护业务引用及事件。已有组件不能支持的视觉细节通过原生组件及素材装配；无法实现时报告具体差距，不扩展转换器 C# 或生成替代脚本。

HTML `ready` 只代表可导入，不等于 Unity 验收完成。导入后查看实际 Unity 截图，核对布局、文字、素材、原生状态、引用和交互，再运行 `--require-unity --unity-project <Unity工程>` 核对完成证据，分别记录设计批准、交付就绪、Unity 验收和设备实测状态；通过后记录“导入转换完成”。

正式 ready 包必须开启 requireSkillApproval 并配置安全的 stagingRoot。暂存区和 StageScene 是持久预览工作区，不能作为测试残留清理。勾选复制后，在 Unity 验收中登记最终 Prefab、Item 和本次交付素材的路径、GUID、文件及 meta 哈希，以及来源转换报告哈希；复制记录提供这些指纹，截图和交互检查针对最终面板。默认复用 TMP 当前默认字体及其现有材质，不创建字体、材质副本或变体；项目明确指定其他已有资源时记录差异。技术示例可用通用入口重新生成并保留未批准状态，不借此绕过正式设计审批。

## 分支 B：Unity MCP 直接替换

元素组图确认并导出素材后，使用 Unity MCP 的已有资源、组件和 Prefab 能力导入 PNG，配置 Sprite、九宫格、像素保真与 tint，再直接更新原面板 Prefab。两项设计确认后，同时导入元素组图和完整面板预览作为参考图。复用原生组件与现有业务行为，不新建视觉脚本或临时脚本文件。

核对实际 Unity 拼接效果、必要状态、文字、引用与原有交互，保存 Prefab 并记录“导入替换完成”。Unity MCP 不可用或工具无法保留关键引用时，停在已确认素材阶段并报告具体阻塞，不切换 HTML 路线或生成脚本绕过。

## 初始化与验证

从本 Skill 目录运行：

```text
python scripts/init_directory.py --root <工作区> --mode full
python scripts/init_directory.py --root <工作区> --mode visual-only
python scripts/validate_directory.py --root <工作区>
python scripts/validate_directory.py --root <工作区> --require-ready
```

默认 `full`；已有工作区自动沿用模式、分辨率和配置，不覆盖现有文件。可指定 `--panel-name`、`--title`、`--width`、`--height`。视觉分支只创建需求、设计和素材目录，没有 HTML 入口。详细目录、证据和校验语义见 [使用说明](references/usage.md)。

## 交付与验收边界

项目内交付元素素材、面板预制体，以及确认后的元素组图和完整面板预览参考图，并保留 Unity 自动维护的 meta。参考图默认放在 `Assets/Art/UI/DesignReferences/{设计集}/ElementGroups/` 与 `Panels/`，按项目规范适配。以 Texture/Default 导入，关闭 mipmaps，NPOT 缩放设为 None，Max Size 足以容纳原图；保持原分辨率与比例，不作为可交互面板整图替代物，不挂到运行时 Prefab，也不新增展示 Canvas。清单、确认记录与程序源码继续保留在工程外。额外组件 Prefab、字体或材质资产仅在用户明确需要时交付，不主动扩展资产体系。

验收检查：实际所需组件覆盖完整；同形素材没有颜色副本；运行时贴图宽高均为 2 的幂次方、尺寸与导入设置未意外降质；已确认的组图和面板预览已原分辨率导入且与批准版本哈希一致；没有丢失引用、异常拉伸或文字裁切；原有交互有效；没有新增视觉 C#。编辑器验证与目标 VR 设备验证分别记录，未测项目保持待验证。
