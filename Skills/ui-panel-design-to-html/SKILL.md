# Unity UI 面板与可复用元素工作流

先确认面板预览，再确认当前项目所需的元素组图；之后按用户意图选择 HTML 转换或 Unity MCP 直接替换。交付到项目的内容包括元素素材、面板预制体，以及用户确认后的元素组图和完整面板预览参考图，不为视觉效果创建或修改 C#、主题 ScriptableObject、Shader 或临时 Editor 脚本。复用现有业务逻辑与原生组件。

## 选择入口与分支

- 只要求“新文件目录”或 HTML 工作区：运行初始化与结构校验，交付未审核草稿后停止，不设计业务控件或制造审批。
- 只要求预览、视觉稿或风格探索：只交付当前要求的未批准设计图后停止；未请求后续落地时，不以分支 B 的 ready 条件推动导出或 Unity 替换。
- **分支 A：完整流程**。未明确限定仅视觉优化的面板设计请求，默认走面板确认 → 元素组图确认 → HTML 实现与验收 → 用户要求时转换到 Unity。
- **分支 B：仅视觉优化**。用户明确只优化原有面板视觉时，面板确认 → 元素组图确认 → Unity MCP 直接导入并替换原内容。不生成 HTML/CSS/JS，不执行浏览器验收、转换器或其安装步骤。
- 已有面板预览或工作区：核对其确认记录与文件版本，从适用阶段继续，不重复已完成步骤，不擅自清理已有实现。更改组图只重新确认受影响组；布局或整体视觉变化才重新确认面板。

## 无参考设计与 XR 风格入口

开始整体设计前，先核对项目平台、显示类型、现有输入和已批准风格。仅初始化时跳过本节；初始化器的颜色与布局只是占位，不是正式设计方向。

- 默认以黑灰、中性灰或淡蓝科技配色打底，用淡蓝/蓝色突出操作；不主动采用紫色、薰衣草色或紫蓝渐变。四种方向主要通过结构与层级区分，不以平台名称推断必须使用某种品牌色。语义告警、危险和成功状态保留各自识别色；用户明确指定或适用的既有批准优先。
- 所有启用的交互组件在**默认、未悬停状态**就要能辨认，按角色遵循[交互组件可辨识规范](references/game-contracts.md#交互组件可辨识规范)：独立动作按钮、输入和拖动控件具有可辨形态；导航区域仅需与底图轻微不同，也可沿用底图，普通导航项不铺高对比色块。检查必要图形/状态标识对相邻背景至少 3:1、普通控件文字至少 4.5:1，不把这一数值强制套到导航底色或每个容器。次操作不应弱到像禁用；同时检查所需各类控件。
- 有用户参考或适用批准时优先沿用，不强制套预设或重新选风格。无参考且没有已批准体系时，读取[风格选择、组件配方与 XR 检查](references/game-contracts.md#无参考设计与-xr-风格包)，实际查看候选方向的内置 PNG，再以同一代表页面制作两套完整预览：PICO 默认 `pico-spatial` / `microsoft-mrdl`，Meta 默认 `meta-friendly` / `microsoft-mrdl`，未指定平台默认 `meta-friendly` / `spatial-soft`；用户明确指定一套或其他风格时服从用户。
- 两套保持相同业务内容、画布、主体尺寸和输入条件；组件结构、布局或表面层级须有实质差异，不能只换色。轻量美化保持原布局时，通过组件结构和表面处理区分。说明每套的设计意图及现有组件装配方式，不新增业务控件来制造丰富度。
- 风格选择并入原有**面板预览图确认**，不增加第三道审批；选定后扩展其余面板。面板确认前不生成正式元素组图或业务 HTML。内置组件一览是未批准的风格范例，不替代当前项目元素组图或产生素材批准。
- 按操作职责选择主/次按钮、工具按钮、操作卡、设置行、数据行与状态提示的结构，不把所有元素套成相同圆角卡片。中性素材复用仅约束同形颜色变化，不要求所有 Button 共用一种造型。
- 图标优先复用项目批准素材；缺少时按[图标来源与制作](references/game-contracts.md#图标来源与制作)选择 Fluent Filled、Phosphor Fill 或 Heroicons Solid，同一项目保持一致并保留来源与许可；不以 emoji 或线性图标占位。
- 提交预览前自评业务层级、中文排版、图标一致性、必要状态、空间可读性与 UGUI 可实现性；发现问题先修订。VR 无描边、POT、TMP 及业务引用保护继续适用。空间反馈按项目已有能力表达，不因选了平台风格自动安装 SDK、开启手势或生成视觉脚本。

## 共用设计规则

- 仅制作当前需求实际涉及的组件和状态。Button、Toggle、InputField、Dropdown、Slider、Scrollbar、Scroll View 是参考类型，不是制作清单。先核对已有 Prefab、绑定与 Sprite；不因列举了类型而新增控件或改变业务职责。
- **默认完整画布为 1920×1080，面板主体按下方[尺寸档位](#面板尺寸档位与画布占比)选择**。新建适用的屏幕 Canvas 时使用相应 Canvas Scaler 参考分辨率；已有明确配置优先沿用并记录差异。World Space Canvas 保持项目的世界尺寸和 XR 配置，以参考布局组织 RectTransform，不擅自切换 Canvas 模式。
- 尽量保持原始素材尺寸与像素细节，不按 RectTransform 显示尺寸缩小源图。检查 Max Size、压缩和平台覆盖，避免意外降质；VR 清晰度结合观看距离与世界尺寸验证，不能仅凭 1920×1080 宣称达标。低分辨率源图需要重制时报告；直接放大不视为恢复细节。
- **所有新制或本次正式导出的元素素材贴图**（包括底板、按钮、边框、图标、进度图形等）的宽和高均采用 **2 的幂次方**（可为长方形，例如 1024×128）；优先向上选择尺寸，不降低原始细节。优先从矢量源按目标尺寸重制，位图保持原像素，不强拉伸。0.3.0 HTML 转换不支持非整图 contentRect 的透明补边：优先重制为无需补边的 POT 素材；需要补边时先转人工适配，不登记为可直接转换。记录有效区域和九宫格。纹理尺寸与 RectTransform 显示尺寸独立。元素组图和面板预览属于参考图，保持原布局分辨率（默认 1920×1080），不强制变为 POT 或裁切。
- **每张面板预览使用纯色画布背景，画布颜色必须与面板主体/元素图片的主色明显区分**，以清楚显示边界、圆角和透明效果。例如深色面板使用中性灰色画布；不把面板主色直接作为画布色。各面板可复用同一合适的对比底色，不必各用不同颜色。不叠加庭院场景、照片、纹理、棋盘格或其他环境装饰。每个面板单独输出，清楚标注画布宽×高和面板主体宽×高，标注放在主体外，不遮挡界面。透明度在纯色底上检查；额外明暗背景验证若实际需要，另存验收证据，不混入供确认的正式面板预览。
- **VR 项目的所有元素组件素材不设计边缘描线、轮廓线或细描边框**，包括按钮、底板、内衬和进度图形；不额外导出 Outline/Border 轮廓素材。使用实色/半透明填充、明暗、间距与留白区分层级和状态，保留平滑 Alpha 圆角。装饰性细分隔线优先改为留白。九宫格 border 是切片边距元数据，可正常使用；审核图的尺寸标注线不属于运行时素材。实际 VR 锯齿仍须设备验证，不因去掉描边宣称已解决。
- **多面板总览必须清楚显示每张完整画布的独立区域**：保留整个 1920×1080 范围，以一致比例展示，用与画布不同色的间隔区或审核边界框分开。不得把同色画布无缝拼接，也不得把每个面板分别裁切放大到看似一样大。标明主体宽高，以及占画布宽、高的百分比；必要时补充面积占比。画布边界框和尺寸标注仅用于审核，不属于 VR 运行时组件的描边。
- 同一实际组件类型、同一部件内，相同形状仅颜色不同，只输出一份白色或统一中性色素材，保留透明度，用各物体的 `Image.color` 改色；按钮颜色状态使用原生 Selectable Color Tint。形状、纹理或透明度结构不同才增加素材；真实多色图案不强行合并为单色遮罩。
- **素材、元素组图使用组件缩写前缀**，例如 `Btn_Primary_Background.png`、`Tgl_Option_Surface_Off.png`。禁止跨组件类型复用；Button/Toggle 的子 Image 按所属控件分类，不能用 `Img` 绕过。完整映射与命名规则见 [组件与素材命名](references/component-naming.md#素材与元素组图命名)。不为了素材命名批量改动现有物体名、绑定或 GUID。
- Toggle 每个样式提供 Off/On/Disabled 三张完整 Surface，状态图同画布与对齐；不规则造型不拆成几何碎片，不再叠加 Checkmark。三图是项目契约，Selected 不是 On。使用转换器已有的通用 `UiToggleStateGraphic`；需要 DisabledOn/DisabledOff 或 Mixed 时报告契约差异，不生成面板专属脚本。
- 游戏级素材同步、部件拆分、去重与三态规则见 [项目素材契约](references/project-assets.md)。设计预览前只读核对现有批准素材；正式 Unity Prefab 生成/导入前，同步当前游戏所有已确认素材。同步不授权在设计确认前写入 Unity。
- 文字保留为 TMP，普通界面沿用项目 UIKit/UIRoot 管理和正式 Prefab 路径。保护 GUID、组件引用、UnityEvent 和序列化字段；不绕开项目流程创建独立普通 Canvas。

## 面板尺寸档位与画布占比

同一项目优先复用少量尺寸档位。先列出本次范围内各面板的用途、档位、主体宽高及完整画布宽高，再制作预览；全项目任务须覆盖全部面板。相差不大的尺寸沿用同一档，不因少量留白差异单独新增尺寸；确需例外时说明内容密度、可读性或交互上的原因。以下为未另行约定时的默认方案，用户指定及已有项目配置优先，轻量美化不自动改变现有布局或主体尺寸。

| 档位 | 面板主体尺寸（布局像素） | 适用界面 |
| --- | --- | --- |
| A：完整数据页 | **1920×1080** | 仪表盘、密集表格、多图表、复杂姿态/参数调整页 |
| B：标准主面板 | **1600×900** | 主菜单、内容选择、常规设置、引导等页面 |
| C：紧凑确认窗 | **960×480** | 开始/结束确认、短提示、少量操作的弹窗 |
| D：自适应提示 | **按文案、图标和内边距自适应** | Toast 等轻量消息；480×120 仅可作设计参考，不是固定尺寸、最小值或最大值 |
| W：世界空间操作卡 | **沿用项目本地布局尺寸** | 锚点等对象旁操作卡，例如 260×400；不强制套用屏幕档位，也不据此改动世界缩放或观看距离 |

- **区分画布与主体。** 未另行指定时，单页原始预览均保留完整 **1920×1080** 画布；B/C/D/W 主体按实际大小放在其中，不放大填满画布，不要求各档主体都是 16:9。默认居中展示，原界面已有锚点位置时沿用并记录。主体尺寸不改变 Canvas 参考分辨率，也不改变运行时 Sprite 的 POT 导出要求。
- **用图像体现占比。** 多面板总览中的完整画布按同一缩放比例放置，画布之间留明确间隔；尺寸与占比标注置于画布外。A 档占画布宽/高均为 100%；B 档均为 83.3%；C 档宽为 50%、高为 44.4%。面积占比按主体面积除以画布面积计算，不用文本标注代替真实大小关系。
- **自适应与世界空间须如实标注。** D 档按当前示例文案的实际渲染尺寸标注，并注明尺寸可随内容变化。W 档注明本地布局尺寸与预览比例，默认以本地 UI 像素 1:1 放入参考画布；若另附放大细节图，单独标注倍数，不混入同尺度比较，也不把布局像素占比当成 XR 物理尺寸。
- **分开记录尺寸。** 需求、布局清单与预览元数据分别记录档位、主体尺寸和画布尺寸，沿用当前契约的字段；不把 B/C 主体宽高传成工作区画布分辨率，不用主体尺寸裁切正式预览。

## 共用步骤与确认节点

| 步骤 | 动作与产出 | 确认节点 |
| --- | --- | --- |
| 1. 需求核对 | 核对原有面板与素材，记录实际需要的类型、元素、用途、状态和引用位置 | 仅把实际需求写入清单 |
| 2. 整体预览 | 无参考时先给同一代表页面的两套方案；使用纯色画布，标注画布及主体宽×高，检查层级、组件、必要状态与 XR 条件 | **面板预览图确认**，同时确认风格方向 |
| 3. 独立元素组图 | 每个可复用结构单独成图，展示尺寸、必要状态、图层、九宫格与在面板中的拼接效果；配色演示共用中性素材 | **元素组图确认**，逐组记录真实确认和版本 |
| 4. 素材导出 | 导出拆分 PNG，记录组件前缀、原始/导出像素尺寸、边距、用途、tint 与面板使用位置 | 与已确认组图对应，不用整图裁片代替可编辑控件 |

面板未确认前不制作正式元素组图；元素组图未确认前不进行最终素材导出、HTML 制作或 Unity 替换。组图审核可以包含中间素材候选，最终交付必须来自已确认版本。两次确认均须来自用户真实意见；使用已有批准图时记录适用版本与限定条件。

两个分支共用 `design/element-groups.json` 与审核记录，格式见 [清单与确认契约](references/manifests.md)。初始化不生成批准记录；结构校验不能替代视觉判断。

## 分支 A：HTML→Unity

元素组图确认后，读取 [HTML 契约](references/html-contract.md)，确定语义化物体名、原生类型、绑定、动态 Item 和辅助节点，生成 HTML/CSS/预览 JS 及清单。按确认尺寸对照面板和组图验收布局、外观及实际需要的状态；用现有比较脚本辅助判断。只有两次审批与 HTML 验收证据有效时标记 `ready`。

用户要求转换时，使用项目已有 `com.nex.html-to-ugui`，按其 README 操作；不擅自安装依赖。需要编辑器操作时使用可用的 Unity MCP 工作流。HTML/CSS/JS、清单和确认记录保留在工程外；已确认的元素组图和完整面板预览另导入 Unity 作为参考图。新游戏设置 projectName 与项目根目录 project.assets.json，先查看只读计划，再统一同步到 Assets/HtmlToUGUIStage/{GameName}/Sprites（RawImage 使用 Textures）；所选面板的 Item、主 Prefab 与报告生成到 {GameName}/{PanelName}。单面板也检查整个项目素材全集；未设置 projectName 的旧示例保留旧布局，不作为新游戏流程。Skill 包开启 requireSkillApproval，字体复用项目 TMP 默认字体及现有材质。导入窗口更新 Assets/HtmlToUGUIStage/StageScene.unity，原场景保持不变。通过 Tools → HTML to UGUI → 面板暂存与复制 窗口逐个预览面板，勾选需要的面板并查看复制计划后，才复制到正式目录；复制会重定向 Item 和图片引用，保留暂存内容。正式目录仅包含运行资源，复制记录保留于暂存目录。已有业务面板仍需项目适配以保护业务引用及事件。已有组件不能支持的视觉细节通过原生组件及素材装配；无法实现时报告具体差距，不扩展转换器 C# 或生成替代脚本。

HTML `ready` 只代表可导入，不等于 Unity 验收完成。导入后查看实际 Unity 截图，核对布局、文字、素材、原生状态、引用和交互，再运行 `--require-unity --unity-project <Unity工程>` 核对完成证据，分别记录设计批准、交付就绪、Unity 验收和设备实测状态；通过后记录“导入转换完成”。

正式 ready 包必须开启 requireSkillApproval 并配置安全的 stagingRoot。暂存区和 StageScene 是持久预览工作区，不能作为测试残留清理。勾选复制后，在 Unity 验收中登记最终 Prefab、Item 和本次交付素材的路径、GUID、文件及 meta 哈希，以及来源转换报告哈希；复制记录提供这些指纹，截图和交互检查针对最终面板。默认复用 TMP 当前默认字体及其现有材质，不创建字体、材质副本或变体；项目明确指定其他已有资源时记录差异。技术示例可用通用入口重新生成并保留未批准状态，不借此绕过正式设计审批。

## 分支 B：Unity MCP 直接替换

元素组图确认并导出素材后，使用 Unity MCP 的已有资源、组件和 Prefab 能力导入 PNG，配置 Sprite、九宫格、像素保真与 tint，再直接更新原面板 Prefab。两项设计确认后，同时导入元素组图和完整面板预览作为参考图。复用原生组件与现有业务行为，不新建视觉脚本或临时脚本文件。

核对实际 Unity 拼接效果、必要状态、文字、引用与原有交互，保存 Prefab 并记录“导入替换完成”。Unity MCP 不可用或工具无法保留关键引用时，停在已确认素材阶段并报告具体阻塞，不切换 HTML 路线或生成脚本绕过。

## 初始化与验证

`E:/html_to_unity_ugui_workflow/UnityProject` 是 Skill 维护示例路径，不是用户目标工程，也不保证本机存在；实际工程以当前任务和配置为准，不自动创建或切换到示例工程。游戏源包统一使用 `Workspaces/{GameName}/Panels/{PanelName}/`；游戏根保留 `project.assets.json`、共享素材、项目审核与工具。初始化器在已有项目清单的 `Panels/` 下自动设置 projectName、相对 html/ 的 `projectDirectory=../../..` 及游戏暂存路径。批量导入选择游戏根目录。维护示例为星港六面板，旧 Example 三面板已移除。编辑器菜单为“导入单个面板...”“导入整个项目...”“面板暂存与复制...”。

从本 Skill 目录运行：

```text
python scripts/init_directory.py --root <工作区> --mode full
python scripts/init_directory.py --root <工作区> --mode visual-only
python scripts/validate_directory.py --root <工作区>
python scripts/validate_directory.py --root <工作区> --require-ready
```

默认 `full`；已有工作区自动沿用模式、分辨率和配置，不覆盖现有文件。可指定 `--panel-name`、`--title`、`--width`、`--height`。视觉分支只创建需求、设计和素材目录，没有 HTML 入口。详细目录、证据和校验语义见 [使用说明](references/usage.md)。

新增游戏、多面板风格维护或重新导入时，读取 [游戏契约与统一验收](references/game-contracts.md)。使用游戏级 style/screens/native-assembly 契约及状态、影响计划工具；沿用已有需求和真实批准，不额外制造阶段审批。0.4.1 可按已启用的游戏配置重放原生圆角与 Slider 装配，仍须检查实际图像和业务引用。

## 交付与验收边界

项目内交付元素素材、面板预制体，以及确认后的元素组图和完整面板预览参考图，并保留 Unity 自动维护的 meta。参考图默认放在 `Assets/Art/UI/DesignReferences/{设计集}/ElementGroups/` 与 `Panels/`，按项目规范适配。以 Texture/Default 导入，关闭 mipmaps，NPOT 缩放设为 None，Max Size 足以容纳原图；保持原分辨率与比例，不作为可交互面板整图替代物，不挂到运行时 Prefab，也不新增展示 Canvas。清单、确认记录与程序源码继续保留在工程外。额外组件 Prefab、字体或材质资产仅在用户明确需要时交付，不主动扩展资产体系。

验收检查：实际所需组件覆盖完整；同形素材没有颜色副本；运行时贴图宽高均为 2 的幂次方、尺寸与导入设置未意外降质；已确认的组图和面板预览已原分辨率导入且与批准版本哈希一致；没有丢失引用、异常拉伸或文字裁切；原有交互有效；没有新增视觉 C#。编辑器验证与目标 VR 设备验证分别记录，未测项目保持待验证。
