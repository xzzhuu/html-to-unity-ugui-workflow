# 《星港拾荒者》游戏项目需求

版本：0.1（示例需求草案）  
编写日期：2026-10-22  
配套文档：[UI 需求文档](ui-requirements.md)

## 1. 项目定位

《星港拾荒者》是一款假定的单机科幻探索游戏。玩家扮演星港回收队长，在基地选择废弃设施、准备补给、派遣探索队，并将回收资源带回仓库。

本示例聚焦“出发前准备与任务结算”，用一套相互关联的游戏界面演示本仓库的需求整理、面板设计、元素拆分、HTML 预览和 Unity UGUI 转换流程。题材、名称、数值和文本均为本次虚构，不代表仓库已经实现的游戏功能。

核心体验：玩家能清楚回答“去哪里、带什么、花多少、拿到什么”，并完成一次有反馈的远征。

## 2. 产品假设与范围

| 项目 | 约定 |
| --- | --- |
| 平台 | Windows PC，鼠标与键盘 |
| 运行形态 | Unity 单机演示；HTML 用于交互预览 |
| 画面 | 横屏，参考分辨率 1920×1080 |
| 语言 | 简体中文，保留英文技术标识 |
| 单次演示时长 | 3～5 分钟 |
| 美术方向 | 克制的科幻设备终端，深色底板、青绿色操作强调、琥珀色风险提示 |
| 任务表现 | 固定结果的模拟远征；无实际战斗与场景探索 |
| 数据 | 内置本地示例数据，无服务器 |

第一版包含六个独立面板：基地、远征选择、仓库与整备、设置、确认弹窗、结算。包含三项任务、八类物品和一条完整成功流程。

后续可扩展角色装备、任务失败、商店和实际探索。第一版不安排联网、账号、付费、抽卡、科技树、复杂装备词条、剧情系统与战斗 HUD。

## 3. 核心流程

1. 进入基地，查看信用点、能源及最近任务状态。
2. 打开远征列表，查看任务风险、费用、预计奖励与推荐补给。
3. 打开仓库整备，搜索和筛选物品，将补给加入携行清单。
4. 返回远征面板，确认任务与资源是否满足出发条件。
5. 在确认弹窗中查看费用及携行摘要，确认后扣除出发费用。
6. 模拟远征结束，打开结算面板，展示消耗与奖励；玩家领取后回到基地。
7. 再次查看仓库，核对资源变化；设置可从基地进入并返回。

任务状态：未开始 → 待确认 → 模拟执行中 → 待领取 → 已领取。执行中不得重复派遣；待领取时必须先处理当前结算。

## 5. 数据与规则

### 5.1 初始玩家数据

| 字段 | 初始值 | 规则 |
| --- | --- | --- |
| 队长名称 | 林岚 | 去除首尾空格后 1～12 个 Unicode 字符；禁止换行与控制字符 |
| 信用点 | 2,400 | 非负整数 |
| 能源 | 100 / 100 | 第一版不自动恢复；不会被奖励提升 |
| 携行上限 | 20 kg | 只约束出发携带的补给；仓库材料不计入 |
| 已选任务 | 无 | 首次进入任务页默认选中“废弃货运站” |
| 携行清单 | 空 | 跨面板保留，重置演示时清空 |
| 设置 | 音效开，音量 80，画质“高” | 音量范围 0～100，整数 |

### 5.2 任务样本

| ID / 名称 | 风险 | 状态 | 信用点费用 | 能源费用 | 预计游戏时长 | 固定奖励 |
| --- | --- | --- | --- | --- | --- | --- |
| mission_cargo / 废弃货运站 | 低 | 已解锁 | 100 | 20 | 10 分钟 | 信用点 300、钛矿石 8、合金板 2 |
| mission_signal / 失联信号塔 | 中 | 已解锁 | 200 | 35 | 20 分钟 | 信用点 600、电路板 3、数据芯片 1 |
| mission_reactor / 旧反应堆核心区 | 高 | 未解锁 | 400 | 60 | 30 分钟 | 信用点 1,200、合金板 6、数据芯片 2 |

第三项解锁条件为“后续版本开放”，第一版持续锁定，点击仅展示详情。预计游戏时长是题材信息，实际模拟始终耗时 3 秒。

货运站推荐携带急救包；信号塔推荐急救包和能源电池。推荐属于提示，不设最低携带门槛。

### 5.3 仓库样本

| ID / 名称 | 分类 | 稀有度 | 初始库存 | 单件携行重量 | 用途 |
| --- | --- | --- | --- | --- | --- |
| item_ore / 钛矿石 | 材料 | 普通 | 20 | 不适用 | 基础制造材料 |
| item_alloy / 合金板 | 材料 | 优良 | 5 | 不适用 | 设施修复材料 |
| item_circuit / 电路板 | 材料 | 优良 | 3 | 不适用 | 电子设备材料 |
| item_chip / 数据芯片 | 材料 | 稀有 | 1 | 不适用 | 科技资料载体 |
| item_medkit / 急救包 | 补给 | 普通 | 4 | 1 kg | 成功远征时若有携带，消耗 1 个 |
| item_battery / 能源电池 | 补给 | 优良 | 2 | 2 kg | 第一版可携带；模拟结算不消耗 |
| item_ration / 压缩口粮 | 补给 | 普通 | 12 | 0.5 kg | 第一版可携带；模拟结算不消耗 |

分类：全部、材料、补给。搜索与分类取交集，按名称包含匹配，忽略首尾空格；搜索为空时展示当前分类全部条目。零库存物品保留展示。

### 5.4 整备与结算规则

- 携行数量是库存内的计划分配，不是额外物品；整备时不扣仓库库存。可加入量 = 当前库存 − 已携行量。
- 调整数量使用整数，单次范围 1～可加入量；可加入量为 0 时禁用加入按钮。
- 携行总重量按数量乘单重求和，展示一位小数。加入后超过 20 kg 时拒绝提交并说明还可携带多少重量。
- 已携行物品再次加入时合并数量；减少至 0 则从清单移除。关闭整备页面保留清单。
- 确认出发时重新校验数据。成功提交后一次扣除任务信用点与能源，锁定本次任务和携行快照。
- 执行中和待领取期间禁止调整携行及再次出发。确认弹窗关闭或取消不扣费。
- 领取结算时一次应用奖励与消耗：若快照含急救包，仓库及携行清单各减 1；其他补给保持原值。
- 领取之后清除活动任务，保留剩余携行清单。重复点击领取、重开结算均不得再次加奖励或扣消耗。
- 演示不提供中途取消。关闭应用后的恢复不属于第一版；重新启动恢复初始示例数据。
- “重置演示”在任意任务状态下均可从基地触发，必须确认，并清空活动任务及未领取结果。

## 6. 可重复演示脚本

### 场景 A：完整成功闭环

1. 重置演示，确认信用点 2,400、能源 100、急救包 4。
2. 在仓库携带急救包 3、能源电池 2：重量 7.0 / 20.0 kg；仓库数量暂不变化。
3. 选择废弃货运站，确认费用 100 信用点、20 能源。
4. 确认后信用点 2,300、能源 80；执行 3 秒后显示待领取结算。
5. 结算展示信用点 +300、钛矿石 +8、合金板 +2、急救包 −1。
6. 领取后信用点 2,600、能源 80、矿石 28、合金板 7、急救包 3。
7. 剩余携行为急救包 2、能源电池 2，重量 6.0 kg。再次进入基地或仓库数值一致。

### 场景 B：边界状态

- 选择旧反应堆：显示未解锁原因，出发按钮禁用。
- 搜索“不存在的物品”：显示搜索空态及“清空搜索”。
- 选中应急信标：显示库存 0，加入按钮禁用。
- 携带急救包 4、电池 2、口粮 12 后重量为 14.0 kg；使用专门的超重测试数据将上限改为 10 kg，验证拒绝加入。该测试数据独立于默认演示，不改变正式初始值。
- 使用资源不足测试数据：信用点 50、能源 10，选择货运站后显示两项缺口并禁用出发。
- 修改名称为全空格：应用失败，输入处显示说明；取消时不覆盖原名称。

## 7. 实现职责

| 层次 | 交付职责 |
| --- | --- |
| 本轮需求文档 | 游戏假设、面板需求、交互、样本、状态和验收标准 |
| 后续设计与 HTML | 经确认的面板预览、元素组图、素材、XHTML 与交互模拟 |
| 当前转换器 | 按已有能力生成原生 UGUI/TMP、Panel/Item Prefab、绑定与模板元数据 |
| 接入游戏 | 数据状态、面板导航、搜索筛选、列表实例、资源校验、模拟计时、结算与设置行为 |

HTML 的 JavaScript 不会变成 Unity 业务逻辑。设置页应在预览中真实改变数值和状态；Unity 若尚未接入音频与画质服务，应明确标为“演示设置”，不宣称已改变游戏画质。

## 8. 完成标准

- 六个面板及成功闭环可按配套 UI 需求逐项验证。
- 样本数量、费用、携行重量和结算结果与场景 A 一致。
- 锁定、资源不足、搜索空态、零库存、执行中、待领取和重复领取均有明确行为。
- 设计确认、HTML 验收、Unity 转换与 Unity 业务验证分别记录实际完成状态。
- 不将需求文档、结构校验或静态截图当作游戏已经可玩的证据。
