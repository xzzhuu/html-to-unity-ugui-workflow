# 《星港拾荒者》UI 需求文档

版本：0.1（用于设计与实现的需求草案）  
编写日期：2026-10-22  
依据：[游戏项目需求](game-requirements.md)  
当前交付状态：仅需求文档；尚未制作或批准面板预览、元素组图、HTML 与 Unity 成品。

## 1. 设计目标与范围

通过六个面板演示“基地 → 选择远征 → 整备 → 确认出发 → 模拟执行 → 领取结算 → 基地”闭环。界面同时承担玩法说明和 HTML→UGUI 流程示例两项职责。

优先完成任务信息、动态列表、物品详情、可编辑表单与状态反馈。第一版不增加地图交互、角色三维预览、波形、动态折线图、复杂拖拽和动画系统。

本文件给出可执行的设计输入。尺寸是初始布局建议，最终以用户确认的面板预览为准；不能将本文件视为视觉批准记录。

## 2. 视觉与布局规范

| 项目 | 要求 |
| --- | --- |
| 设计画布 | 1920×1080，横屏；坐标左上原点，单位为设计像素 |
| 主面板范围 | 基地、远征、仓库、设置、结算均为 x=120、y=80、w=1680、h=920 |
| 外侧留白 | 主面板占画布宽 87.5%、高约 85.2%；留白展示轮廓与圆角 |
| 确认弹窗范围 | x=600、y=280、w=720、h=520；占画布宽 37.5%、高约 48.1% |
| 色彩建议 | 底板 #142330，内层 #203745，主操作 #4AD7BB，风险 #F2B65C，错误 #F07878 |
| 文本 | 主文字 #EEF5F7，辅助文字 #AAC0CA；实际按背景验证可读性 |
| 字号 | 页面标题 40，区块标题 28，正文/按钮 24，辅助信息不小于 20 |
| 间距 | 基础 8；主区域间距 24～32；内容内边距 24～40 |
| 点击范围 | 常规按钮高度至少 56；图标按钮点击区至少 48×48 |
| 状态表达 | 文字、图标和填充共同表达，风险与禁用不得仅依赖颜色 |
| 图片与文本 | 图标、底板可用 PNG；名称、数量、费用、说明保留可编辑 TMP |

正式审核预览使用与深色主体明显区分的纯色画布，例如 #89939C。每张预览只展示一个面板，在主体外标注画布与主体尺寸，不叠加太空场景、照片或纹理。多面板总览保留各自完整画布，用间隔区分。

实际游戏中背景可由游戏层提供。确认弹窗的交互遮罩与独立审核预览背景分别处理，不把审核标注做成运行时素材。

第一版按 PC 设计，不含 VR 验收。布局在 1920×1080、1280×720、1920×1200 下等比适配；后两种分辨率不得非等比拉伸，16:10 可留边，不要求重排。沿用项目 UI 根节点及 Canvas 管理；参考分辨率 1920×1080，建议 Match=0.5，最终以项目实际配置为准。

## 3. 面板与导航

| 编号 | 面板名 | 中文名称 | 入口 | 返回方式 |
| --- | --- | --- | --- | --- |
| UI-01 | StarportHomePanel | 星港基地 | 启动/领取结算后 | 顶层页面 |
| UI-02 | ExpeditionSelectPanel | 远征选择 | 基地“选择远征” | 返回基地，保留选中任务 |
| UI-03 | SupplyInventoryPanel | 仓库整备 | 基地“仓库整备”或任务页“调整补给” | 返回来源页，保留携行 |
| UI-04 | GameSettingsPanel | 游戏设置 | 基地“设置” | 应用后返回；取消则放弃草稿 |
| UI-05 | ActionConfirmPanel | 操作确认 | 确认出发/清空携行/重置演示 | 取消或确认后关闭 |
| UI-06 | ExpeditionResultPanel | 远征结算 | 模拟结束/基地“查看结算” | 领取并返回基地；关闭则保留待领取 |

每个面板各用一个 HTML 根节点，根名称、panelName 与主 Prefab 名一致。普通页面同一时间只显示一个；确认弹窗显示在当前页上方并阻断底层输入。

Esc 优先关闭弹窗；其次关闭结算并回基地；在普通子页等同返回/取消。基地 Esc 不退出应用。执行中返回基地不取消任务，基地显示执行状态，任务结束后提示可领取。

## 4. 分面板需求

### UI-01 星港基地 / StarportHomePanel

**信息层级：** 队长与资源 → 主任务入口 → 当前远征状态 → 设置与复位。

- 顶部资源条：队长名、信用点、能源、携行重量。资源不足不得显示负值。
- 左侧主区域约 960×640：标题“星港拾荒者”、说明“整备补给，回收失落资源”、主按钮“选择远征”、次按钮“仓库整备”。
- 右侧状态区约 560×640：当前任务名、状态、携行摘要；无任务显示“尚未派遣远征队”。
- 执行中显示“远征执行中（演示）”与剩余秒数，选择远征按钮禁用；待领取显示“远征完成，等待领取”和“查看结算”。
- 底部提供“设置”“重置演示”。复位必须弹窗确认。

**验收：** 返回基地后资源与整备页一致；执行状态不因页面切换重启；待领取入口能恢复同一份结果。

### UI-02 远征选择 / ExpeditionSelectPanel

**布局建议：** 顶部标题与资源条高 88；内容从局部 y=128 开始，左侧任务列表宽 560，右侧详情宽 960，底部操作区高 96。

- 左侧纵向 ScrollView：动态任务卡，建议每行 520×152、间距 16。卡片显示名称、风险、预计时长、解锁状态及选中标记。
- 右侧显示选中任务名称、简述、风险说明、信用点费用、能源费用、奖励清单、推荐补给及当前携行摘要。
- 奖励同时显示物品名称和数量，不能只用图标。推荐补给明确写“推荐”，避免误解为强制条件。
- 底部按钮：“返回基地”“调整补给”“确认出发”。
- 确认出发前校验；按钮附近列出缺口，例如“还缺 50 信用点、10 能源”。多种缺口同时显示。
- 锁定卡片可选中查看详情；详情显示“后续版本开放”，出发按钮禁用。
- 打开确认弹窗后若状态改变，最终确认必须重新校验；失败时关闭弹窗并回显具体原因。

**状态：** 正常、已选、锁定、资源不足、任务执行中、待领取、加载中、读取失败、任务列表为空。加载与错误为独立验收数据，可通过预览状态入口切换。

**验收：** 切换三项任务时所有详情同步更新；滚动不移动右侧详情；禁用原因无需悬停也可读到。

### UI-03 仓库整备 / SupplyInventoryPanel

**布局建议：** 顶部标题与资源条高 88；第二行分类按钮与搜索框高 64；主体三列分别约 620、440、500 宽，间距 24。

- 分类使用三个普通 Button：“全部”“材料”“补给”。选中分类用业务选中底板和文字状态表示。
- 搜索使用 InputField，提示“搜索物品名称”，提供“清空”按钮；输入即筛选，返回本页保留当前搜索条件。
- 左列纵向物品列表：动态 Item，建议行高 96、间距 12，显示图标、名称、分类、库存、稀有度和选中状态。
- 中列物品详情：图标、名称、说明、库存、单重。无选择时显示“选择物品查看详情”。
- 补给详情提供数量减/加按钮、整数 Slider、当前数量和“加入携行”。Slider 最小值 1、最大值为可加入量；最大值为 0 时隐藏数量控件并显示“无可加入数量”。
- 材料详情显示“制造材料，不能作为远征补给”，隐藏加入操作。数量只有一个可选值时显示固定数量 1，禁用滑块。
- 右列携行清单：动态纵向 Item，展示物品名、已携带数量、总重量，以及“减少 1”“移除”。底部显示总重量及“清空携行”。
- 清空须确认；移除单类物品立即生效；操作失败保留原清单并显示原因。
- 重量用文字与原生 Slider 表现进度；该 Slider 只读，不接收指针事件。按钮附近提示超重原因。
- 底部“返回”回来源页；无需另设保存按钮，操作后即时更新会话中的携行草案。

**状态：** 普通、已选、库存 0、材料不可携带、可加入量为 0、搜索无结果、库存为空、携行为空、超重拒绝、任务锁定。

**验收：** 分类与搜索同时生效；列表更新后保留仍可见的已选物品，否则清空详情；重复加入合并数量；计划携带与仓库库存分别展示，不能让用户误以为已扣库存。

### UI-04 游戏设置 / GameSettingsPanel

**布局建议：** 表单居中宽 1120，每行高 96，标签列宽 240；底部放置取消与应用。

| 字段 | 原生控件 | 行为 |
| --- | --- | --- |
| 队长名称 | InputField | 默认现有名称；校验规则见游戏需求；错误显示在字段下方 |
| 音效 | Toggle | 开/关并显示对应文字；关闭音效不改写音量值 |
| 主音量 | Slider | 整数 0～100，显示当前百分比；音效关闭时仍可调整保存 |
| 画质 | 低/中/高三个 Button | 单选业务状态，不使用 Dropdown；说明“演示设置” |
| 操作 | Button | “恢复默认”“取消”“应用” |

恢复默认只修改表单草稿；应用时校验并写入会话；取消或 Esc 放弃全部未应用修改。应用按钮保持可点击，以便无效输入时给出具体错误。

**验收：** 再次打开显示已应用值；输入全空格不能提交；12 字符正常，超过 12 字符有提示；中文显示完整；取消不改变基地名称。

### UI-05 操作确认 / ActionConfirmPanel

同一结构复用三种模式，运行时填充内容；不创建三个仅文案不同的 Prefab。

| 模式 | 标题 | 主要内容 | 确认按钮 |
| --- | --- | --- | --- |
| 出发 | 确认派遣远征队？ | 任务名、费用、携行摘要、模拟耗时说明 | 确认出发 |
| 清空 | 清空携行清单？ | 只清空计划携行，不销毁仓库物品 | 清空携行 |
| 重置 | 重置本次演示？ | 恢复初始资源、设置与仓库，清除当前任务和待领取结果 | 重置演示 |

包含标题、最多六行正文、费用摘要、取消和确认按钮。点击外部遮罩不关闭；取消和 Esc 关闭。打开时默认焦点落在取消按钮，连续点击确认只提交一次。

**验收：** 底层按钮无法被点击；出发确认被拒绝时不扣费；取消重置不改变任何状态。

### UI-06 远征结算 / ExpeditionResultPanel

**布局建议：** 顶部任务标题与“远征成功”，左侧任务摘要宽 560，右侧奖励列表宽 960，底部固定“领取并返回基地”。

- 展示任务名称、模拟完成状态、出发费用、补给消耗与待领取奖励。
- 奖励使用动态纵向列表，单行包含图标、名称、数量；信用点也作为独立奖励行。
- 急救包未携带时消耗区显示“本次无补给消耗”；不产生负库存。
- 领取按钮首次提交后立即禁用，完成后关闭页面；再次打开已领取记录不提供领取按钮。
- 关闭或 Esc 回基地，保留未领取结果和提醒；奖励在点击领取时到账。

**验收：** 出发费用已扣，领取时不得重复扣；连续点击不重复到账；结算内容来自出发快照，不能被之后的页面显示数据改写。

## 5. 控件、模板与绑定约定

支持控件限定为当前转换器已有的 Container、Text、Image、Button、InputField、ScrollView、Toggle、Slider。动态列表只要求纵向滚动，不使用 Grid、横向滚动和虚拟列表。

| 所属面板 | 主要 Unity 名称 | bindingKey 示例 | 原生类型 / 用途 |
| --- | --- | --- | --- |
| 基地 | Txt_Credits / Txt_Energy | Player.Credits / Player.Energy | TMP，动态资源 |
| 基地 | Btn_OpenExpeditions | Action.OpenExpeditions | Button，进入任务页 |
| 远征 | Scroll_Missions | Missions.List | ScrollRect，任务模板实例容器 |
| 远征 | Txt_MissionName / Btn_StartExpedition | Mission.Name / Action.StartExpedition | TMP / Button |
| 仓库 | Input_ItemSearch | Filter.Search | TMP_InputField |
| 仓库 | Scroll_Inventory / Scroll_Loadout | Inventory.List / Loadout.List | 两个独立 ScrollRect |
| 仓库 | Slider_AddQuantity | Supply.AddQuantity | Slider，整数选择 |
| 仓库 | Btn_AddSupply | Action.AddSupply | Button |
| 设置 | Input_CaptainName | Settings.CaptainName | TMP_InputField |
| 设置 | Toggle_Sound / Slider_MasterVolume | Settings.SoundEnabled / Settings.MasterVolume | Toggle / Slider |
| 弹窗 | Txt_Message / Btn_Confirm / Btn_Cancel | Confirm.Message / Action.Confirm / Action.Cancel | TMP / Button |
| 结算 | Scroll_Rewards / Btn_ClaimRewards | Rewards.List / Action.ClaimRewards | ScrollRect / Button |

上述为核心绑定示例。正式 `elements.json` 必须覆盖全部实际源节点和转换器辅助节点，补齐用途、父级、类型、状态、数据来源及准确名称，不能只记录此表。

| 逻辑模板键 | Unity 根名 | 使用位置 | 模板作用域绑定 |
| --- | --- | --- | --- |
| MissionEntry | Item_MissionEntry | Missions.List | Mission.Select / Mission.Name / Mission.Risk / Mission.LockReason |
| InventoryEntry | Item_InventoryEntry | Inventory.List | Item.Select / Item.Name / Item.Quantity / Item.Icon |
| LoadoutEntry | Item_LoadoutEntry | Loadout.List | Supply.Name / Supply.Quantity / Supply.Weight / Action.Decrease / Action.Remove |
| RewardEntry | Item_RewardEntry | Rewards.List | Reward.Icon / Reward.Name / Reward.Quantity |

每个模板只有一个根节点，不嵌套模板。绑定在所属主面板或模板作用域内忽略大小写后唯一；可以在不同面板或不同模板复用相同键。运行时列表创建、定位、复用与 Content 高度更新由游戏层完成。

Button 的原生 Selected 是导航焦点，不能用它代替任务、物品或分类的持续业务选中状态；业务选中使用独立 Image/文字状态，由预览逻辑及游戏层同步。

## 6. 必须可验收的状态数据

| 数据集 | 配置 | 应看到的结果 |
| --- | --- | --- |
| Default | 使用游戏需求中的初始数据 | 3 项任务、8 类物品、空携行 |
| OneItem | 仓库仅有急救包 1 | 单条布局正常，数量固定为 1 |
| ManyItems | 用唯一 ID 扩展至 30 个物品样本 | 只出现纵向滚动；按钮固定；模板无重叠 |
| EmptyInventory | 库存记录为空 | 显示“仓库暂无物品”，详情与加入操作关闭 |
| SearchEmpty | 搜索“不存在的物品” | 显示“没有找到相关物品”及清空入口 |
| Insufficient | 信用点 50，能源 10 | 货运站显示缺 50 信用点、10 能源 |
| Overweight | 携行上限仅在该数据集设为 10 kg | 4 急救包 + 2 电池为 8 kg；再加入 5 口粮被拒绝 |
| LongText | 12 字队长名、24 字物品名、120 字说明 | 名称省略时详情可读全名；说明换行且不覆盖按钮 |
| Loading / Error | 任务数据模拟加载/失败 | 展示加载文字或“读取失败”与重试按钮 |

预览数据入口放在演示工具层，不混入游戏正式操作区。每个面板可单独预览；要验收跨页面流程时，必须由共享演示状态连接六页，不能把每页独立重置的数据当作完整闭环。

## 7. 素材需求

| 素材组 | 内容 | 复用要求 |
| --- | --- | --- |
| Img_Surface | 主底板、内容卡片、选中底板 | 形状相同的色差用 tint；需要拉伸的底板标注九宫格 |
| Btn_Action | 主/次/危险按钮结构及交互状态 | 同形共用中性背景，使用原生 Color Tint 表达颜色状态 |
| Img_Resource | 信用点、能源、重量、风险、锁定、返回、搜索、关闭图标 | 图标之外保留文字说明 |
| Img_Item | 八种物品图标 | 原创示意，造型与名称对应；不能用整张面板截片替代 |
| Inp_Form | 搜索框与名称框结构 | 可复用同一输入底板 |
| Tgl_Sound | 开关底板及勾选/状态图形 | 使用原生 Toggle；定制图形在 Unity 装配后核对 |
| Sld_Value | 轨道、填充、滑块 | 音量和数量共享造型；重量条仅复用轨道与填充 |
| Scr_List | 列表底板及必要滚动表现 | 本版滚轮滚动，不额外要求独立 Scrollbar |

独立状态图仅在形状、纹理或透明度不同的情况下输出；普通、悬停、按下、禁用等纯颜色变化共用一份素材。不能混用同一控件的 SpriteSwap 与 Color Tint 配置。

运行时 PNG 宽、高各自为 2 的幂，例如底板 512×512、按钮 512×128、图标 256×256；最终尺寸以细节与元素组图为准。纹理尺寸不等同于显示尺寸。当前路线不使用非整图 contentRect 的透明补边素材。

文字不得烘焙进按钮、任务卡和奖励图标。TMP 使用工程已有且覆盖中文的字体及现有材质；缺失字形时记录依赖，不把浏览器字体可见当作 Unity 字体已满足。

## 8. 与当前仓库的实现约束

- 每个面板建立独立准备工作区，保留标准 inputs、design、html 结构；同一目录不放六个根 Panel。
- XHTML 使用明确的像素位置与尺寸，不依赖 flex/grid、媒体查询、百分比、复杂选择器或 JavaScript 布局才能转换。
- 圆角、投影和装饰通过已确认图片与原生 Image 实现，不假设 CSS 效果会自动映射到 UGUI。
- Slider、Toggle 默认生成几何若与确认设计有差异，使用现有原生组件及素材装配后复核，不为视觉需求扩展转换器 C#。
- 图片与 Panel/Item Prefab 先进入 `Assets/HtmlToUGUIStage/{PanelName}/`，由暂存窗口审核后选择复制。
- 主面板正式目标默认是 `Assets/Art/UIPrefab/{PanelName}/`，取消“保留面板名称子目录”后直接进入 `Assets/Art/UIPrefab/`；Item 统一进入 `Assets/Art/UIPrefab/Item/`。图片沿用 `Assets/Art/UI/Sprites/{PanelName}/`；最终以复制计划为准。
- 已确认完整面板图与元素组图作为参考纹理单独导入 `Assets/Art/UI/DesignReferences/StarportSalvage/`，不参与运行时面板装配。
- HTML、CSS、预览 JavaScript、需求和审核证据留在 Unity 工程外；暂存区和 StageScene 保留供持续检查。
- 转换器生成结构与通用绑定元数据。游戏层另行实现导航、业务选中、搜索、数量逻辑、事件订阅、模拟计时与一次性结算。

建议第一批先制作 SupplyInventoryPanel，验证列表、详情、数量及素材复用；第二批制作远征、确认、结算与基地，连接闭环；第三批完成设置和边界状态。
